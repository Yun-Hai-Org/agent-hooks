【盈米安全编码规范 - 编写代码时必须遵循】

本规范为强制要求，AI 在编写、修改任何代码时必须遵守以下条款。

一、权限与数据安全
- 【强制】隶属于用户个人的页面或功能必须进行权限控制校验。防止未做水平权限校验即可访问、修改、删除他人数据（如查看他人资产）。
- 【强制】用户敏感数据禁止直接展示，必须对展示数据做业务需求最小化的脱敏处理。正例：中国大陆手机号显示 133****1564；身份证号隐藏出生年月日。
- 【强制】用户请求传入的任何参数必须做业务需求的最小可变范围限制，并做有效性验证。忽略校验可能导致：page size 过大导致内存溢出、恶意 order by 导致慢查询、缓存击穿、SSRF、任意重定向、SQL/Shell/反序列化注入、ReDoS 等。

二、SQL 与注入防护
- 【强制】用户输入的 SQL 参数严格使用参数绑定或 METADATA 字段值限定，防止 SQL 注入；禁止字符串拼接 SQL 访问数据库。

三、XSS 与输出安全
- 【强制】禁止向 HTML 页面输出未经安全过滤或未正确转义的用户数据，防止 XSS 跨站脚本攻击（窃取 cookie、钓鱼、挂马等）。

四、CSRF 与重定向
- 【强制】表单、AJAX 提交必须执行 CSRF 安全验证，防止跨站请求伪造。
- 【强制】URL 外部重定向传入的目标地址必须执行白名单过滤，防止钓鱼。

五、业务与资源防护
- 【强制】使用平台资源（短信、邮件、电话、下单、支付、结算）必须实现防重放机制：数量限制、疲劳度控制、验证码校验，避免被滥刷导致损失。
- 【强制】发帖、评论、即时消息等用户输入场景必须实现防刷、内容违禁词过滤等风控策略。

六、文件与配置安全
- 【强制】文件上传功能必须对文件大小、类型进行严格检查和控制，防止恶意文件上传与远程执行。
- 【强制】禁止外部文件存储在可执行目录（如 Web、appBase）；建议保存在专门的文件服务器。避免路径拼接；保存目录建议后台写死并对文件名做校验（类型、长度），文件名建议替换为随机字符串。
- 【强制】配置文件中严禁明文写入密码；必须写入时须采用可靠加密措施。

七、JWT 安全
- 【强制】严禁在 JWT 中携带任何敏感信息（如 key、pass）。Payload/Header 仅 Base64Url 编码，可被解密。
- 【强制】服务层验证 JWT 时必须校验签名；必须明确声明签名算法，禁止配置 header 的 ALG 为 None。
- 【强制】签名秘钥须为复杂密码（至少 16 位，含数字、大小写字母及特殊字符）；Payload 中 EXP 时效性越短越好。

八、合规与内容
- 【强制】所有生成或建议的内容均不得出现中国法律与监管禁止的违禁内容，包括但不限于：涉黄、涉诈、涉恐、涉政等违禁字样或等效意图。无论来源是用户输入、模型训练数据中被恶意引入的内容，还是 Agent 抓取网络得到的内容，均不得出现在研发代码仓库中。

编写代码时请逐条对照以上规约，在实现功能的同时满足安全与合规要求。
